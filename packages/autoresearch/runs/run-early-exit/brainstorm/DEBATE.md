# Brainstorm Debate

## Debate gap-a
- ATTACK: Feasibility (unfalsifiable by construction): If the method is truly lossless — p16/p17 guarantee accepted-distribution matching so the verify step corrects every draft error — the final output distribution equals the full model's. Per-group final accuracy is therefore unchanged by construction, so 'differential harm to demographic groups' is expected to measure ~0 regardless of the model. The audit cannot distinguish 'no harm' from 'the test is vacuous'; it risks a null result that falsifies nothing.
- ATTACK: Feasibility (severed causal chain): Acceptance rate is an intermediate artifact of the draft head, not a property of the final output. Its fairness consequence only becomes a risk if it transfers to final per-group error — but the losslessness guarantee severs exactly that link. So 'acceptance-rate as group-conditional risk' points at a metric with no downstream group harm to control, making the risk-control target ill-defined.
- ATTACK: Feasibility (small/degenerate signal): d1_03 shows early-exit decoding rarely engages on modern LLMs and acceptance is already near-perfect, so the group variance in acceptance rate may be tiny or a measurement artifact; d2_01 reports entropy/confidence gaps are small (d=0.06-0.16). There may be no meaningful per-group acceptance-rate spread to audit on realistic models. Instrumenting LayerSkip/Kangaroo draft-verify internals also needs model-specific hooks and public annotated generation sets, raising setup cost.
- ATTACK: Novelty (occupied framing): 'Group-conditional risk under control' is already the core of gap-c and n3 via d2_03 (hierarchical group-conditional conformal risk control) and p58 (selective prediction / abstention as risk control). gap-a effectively swaps the confidence threshold for an acceptance-rate threshold over the same two-stage exit + risk-control machinery — the variable is renamed, the mechanism is not new.
- ATTACK: Novelty (restatement): 'Acceptance rate is group-conditional' is nearly a corollary of d2_01, which already establishes that token-level entropy/confidence differs across demographic groups. Since acceptance rate is a proxy for exactly that confidence signal, the novel content reduces to re-labeling a known finding rather than exposing a new axis.
- ATTACK: Novelty (null-contribution risk): The honest result of a lossless-method fairness audit is likely 'lossless implies no measured harm' — a null/audit contribution with no mechanistic insight, no new method, and no mitigation. For a top venue that is a weak novelty claim, especially against n3's concrete risk-controller deliverable. Also note d3_05 already flags that acceleration effects are strategy/model-specific and unpredictable, so a single-model finding would not generalize.
- SUPPORT: The underlying premise — allocation of compute is not fairness-neutral — is well-supported and worth keeping: d3_05 (inference acceleration changes bias significantly but unpredictably), p38 (compression/pruning has disparate impact), and d2_01 (token-level entropy differs by demographic) all point to this.
- SUPPORT: Framing bias as residing in *where compute is spent* (draft-accept vs. verify) rather than only in the final output distribution is a real, under-explored angle; S6 treats speculative decoding as pure latency with no fairness axis.
- SUPPORT: Acceptance rate is a cheap, real-time, model-introspectable per-group signal that could serve as a monitoring knob or control variable — a practical and auditable target, if the measured effect can be made non-zero.
- REVISED: Drop the losslessness assumption so the effect is observable, and keep the id. Revised (id gap-a): "Under a bounded latency/compute budget where lossless self-speculative verification is not affordable for every token, which draft-verify compute-skip policy (accept vs. verify which tokens) redistributes verification error onto specific demographic groups? If per-group acceptance rate (or mean accepted draft-length) tracks group-conditional verification error under a compute cap, can acceptance rate be used as a group-conditional allocation signal to control worst-group error — a fairness-aware token-compute-skip criterion rather than a request to audit whether a lossless method stays lossless, which is trivially unchanged by construction?" Cheap test keeps instrumentation on LayerSkip/Kangaroo but adds a compute-cap that forces dropping full verification for some tokens, so per-group acceptance rate vs. per-group error become jointly measurable. Evidence remains d3_05, p16, p17, p15, d2_01, d1_03. Risk: no longer vacuous by construction, but requires a compute budget that makes the lossless verification genuinely infeasible; if per-group acceptance-rate spread stays small on modern models, the effect may still be thin.

The depth lever is partly composed of redundant layers (p25) and the exit gate reads confidence, so a decomposition cannot attribute harm cleanly to one; the measurable result is a correlational fit, not a causal answer, which the target's own risk admits (group labels confound difficulty). No standard public artifact exposes an injection point for forced per-group exit-depth, so the experiment needs bespoke instrumentation on LayerSkip/PABEE, and d1_03 warns modern models rarely exit early — the depth signal may be too thin to detect any mechanism.

It heavily overlaps f1 (already audits per-group fairness vs a shared threshold) and n1 (measures fairness footprint + designs group-conditional exit thresholds), so the only differentiator is the 'detect-and-predict' phrasing, which never gets turned into a concrete criterion. It reuses existing models (LayerSkip/Kangaroo/PABEE) on public bias benchmarks, so setup/angle/eval add nothing beyond what is already on the table. The core promise 'harm becomes predictable' is asserted but the predictor, and how its accuracy would be measured, are never defined — novelty is claimed, not demonstrated.
- SUPPORT: Uniquely mechanism-driven rather than black-box: unlike the plain 'did bias change' audits (f1), it asks WHY adaptive compute redistributes harm, which is a stronger scientific contribution and its best distinguishing asset.
- SUPPORT: Grounded in concrete, cited mechanism: d1_06 shows the MoR router allocation is learned and therefore auditable; d1_01 ties early-exit decisions to group fairness; d2_01 shows the exit-gate entropy signal already differs by group; p25 shows deep layers are largely redundant; p11 ties per-instance complexity matching as the underlying mechanism — so the disaggregation rests on real evidence rather than a claim.
- SUPPORT: The forced exit-depth lever is a controllable causal variable, so the cheap test is a genuine controlled experiment (perturb depth, observe per-group error) rather than passive correlation, and is single-GPU feasible.
- SUPPORT: If the 'detect-and-predict' promise is converted into an explicit in-loop group-conditional signal (e.g., per-group mean accepted depth or calibration slope) that measurably predicts worst-group error, it yields a transferable, actionable criterion that none of the other candidates delivers end-to-end.
- REVISED: Revised (id gap-b): "Determine which mechanism makes adaptive-compute harm group-predictable by isolating each candidate lever under forced control — is worst-group error driven by (i) a group-correlated exit-depth/router allocation, (ii) per-group exit-confidence miscalibration, or (iii) group-differential layer redundancy — then turn the winning mechanism into a measurable group-conditional early-exit signal that predicts worst-group error under a depth budget, i.e. a detect-then-predict rule instead of a post-hoc audit. Decouple the depth lever by forcing exit-depth/exit-epoch; test the calibration lever by per-group temperature/Platt recalibration of the exit gate; test the redundancy lever with a cross-layer-similarity/linear-separability proxy (p69, p64); and report which single in-loop signal (per-group mean accepted depth vs per-group calibration slope vs redundancy proxy) best predicts per-group error on held-out groups, establishing whether group harm is predictable from a cheap signal available during decoding." Cheap test: on one early-exit model (LayerSkip or PABEE/DeeBERT) over a demographic-annotated set, sweep forced exit-depth and record per-group error/ECE; compute per-group mean accepted depth, per-group calibration slope, and a cross-layer redundancy proxy; fit a predictor of per-group error from these three and report which explains worst-group error. Evidence: d1_06, d1_03, p11, p25, d2_01, d1_01, p69, p64. Risk: mechanisms overlap so attribution stays correlational and may need a designed ablation to confirm causality; group labels confound difficulty; d1_03 warns the depth signal may be thin in modern models; if the three signals are highly correlated the decomposition collapses into one factor, weakening the 'which mechanism' answer.
## Debate gap-c
- ATTACK: FEASIBILITY: The 'preserve efficiency gain' clause is directly contradicted by the evidence gap-c itself cites. d2_03 shows HG-CRC reaches ~0% per-group violation only at a 22-37-point participation/coverage cost; in early-exit, participation/coverage IS the efficiency gain (tokens accepted at depth < full). So group-conditional risk control and the early-exit speedup are the same resource, and the claimed unification is likely a Pareto-dominated frontier — the direction risks being a restatement of d2_03's known tradeoff rather than a result. d1_03 compounds this: modern models rarely exit early, so there may be little efficiency to preserve in the first place; if the base speedup is thin, the 'both at once' objective is vacuous (nothing to give up and nothing gained).
- ATTACK: FEASIBILITY: Group-conditional calibration needs enough per-group data to set per-group thresholds; d2_03 itself flags that results are benchmark-specific (MMLU-Pro may abstain entirely) and that small groups overfit. Combined with d1_03's warning that early-exit suitability is architecture/scale dependent, a single model + single benchmark cheap-test would not establish that the controller generalizes — the feasibility claim is fragile exactly where it needs to be strong.
- ATTACK: NOVELTY: gap-c is dangerously close to a re-instantiation of d2_03. d2_03 already builds hierarchical group-conditional conformal risk control for selective prediction, and p58 frames abstention/selective prediction as the error-regularization mechanism, p56 warns raw entropy thresholds are unsafe. 'Use a group-conditional risk controller as the early-exit stop rule' is the same machinery with a different knob — the novelty reduces to a latency coupling that d2_03 does not explicitly model, which is a minor delta, not a new result. With candidate n3 already flagging this exact overlap, gap-c risks being redundant with the existing conformal line.
- ATTACK: NOVELTY: The likely outcome — an efficiency-vs-worst-group-error Pareto frontier showing an unavoidable tradeoff — is a 'can't have both' negative result. That is low-novelty because selective-prediction literature (p58, p56) and d2_03 already establish the coverage/error tradeoff. Proposing to 'bound per-group error while preserving efficiency' sets up a defensive framing that, if it fails, contributes no new insight and, if it succeeds, is merely confirming a known tradeoff shape.
- SUPPORT: The unification is coherent and well-grounded: d1_02 gives adaptive bandit-exit risk control, d2_03 gives group-conditional conformal risk control, p58 gives the abstention/error-regularization framework, and p51/p54/p61 give the calibration machinery to make a shared threshold group-fair. These are real, buildable components rather than wishful thinking.
- SUPPORT: d1_01 establishes early-exit x group-fairness as a real, connected mechanism, and d2_01 shows the exit-gate signal (next-token entropy / confidence) is already group-differential. This justifies a group-conditional threshold over a global one, giving the idea a concrete mechanism rather than an assumption.
- SUPPORT: The single, focused objective (unify exit threshold with abstention risk control) is cheaply testable: a confidence/calibration threshold sweep on an existing early-exit model over a demographic set, reporting efficiency-vs-worst-group-error on the same axes as vanilla exit and HG-CRC. low compute, no retraining, 1-2 cycles.
- REVISED: Keep id gap-c. Revise from a 'achieve both' victory claim to a characterization: "Does a group-conditional risk-controlled early-exit threshold admit a joint efficiency-safety region, or is it Pareto-dominated? Model the early-exit stop rule as a selective-prediction decision where the model may exit (buy latency) or continue (buy per-group risk), and explicitly emit the per-token-per-group exit-depth-coupling that d2_03's classification-setup does not capture. Rather than claim to bound per-group error while preserving the full speedup, chart the efficiency-vs-worst-group-error Pareto frontier, locate the efficient-safe region where both are simultaneously satisfiable, and quantify the efficiency cost of each per-group violation guarantee. Mark the novel contribution as the token-level duration coupling to per-group risk control (d2_03 optimizes a coverage scalar; here the coverage term is per-token exit-depth, so participation and latency are the same budget), not as another run of HG-CRC. Scope the cheap test to one early-exit model + one demographic benchmark with a per-group calibration threshold sweep, and treat 'no efficient-safe region' as a legitimate, reportable finding (a negative characterization still advances the question gap-c poses). Evidence: d2_03, d2_01, d1_01, d1_02, p58, p56, p51, p54, p61, d1_03."
## Debate f1
- ATTACK: [gap] f1 is a pure audit ('does X shift Y?') that measures but never acts. It inherits the exact weakness it was meant to fix: no mechanism isolation and no criterion. It sweeps a shared confidence threshold yet never tests whether a group-conditional threshold would flatten the harm, so it cannot answer the actionable question (can per-group depth allocation be a fairness lever).
- ATTACK: [gap] The single shared confidence threshold is a strawman by construction: d2_01 shows the gate signal (next-token entropy) already differs across race/gender. A shared gate therefore cannot give equal exit-depth or equal per-group error, so the audit is measuring a deliberately broken configuration rather than the fairness-relevant design. It is a measurement-design error, not a finding.
- ATTACK: [gap] d3_04 reports up to 21% of responses flip bias state with NO aggregate change and asymmetric per-group shifts (+18.6%/-14.1%) cancel in aggregate. An aggregate per-group error/ECE audit at a shared threshold can report 'no fairness shift' while actually masking large asymmetric redistribution — the audit's core metric is the wrong one for the phenomenon it targets.
- ATTACK: [gap] d1_03 warns modern LLMs rarely exit early (low exit potential, dense > MoE/SSM, base > tuned, >20B). Under this boundary the measured depth difference (and any fairness delta) may be too small or too noisy to be a robust, interpretable finding — a low-power null that is an artifact of architecture rather than of the policy. Low statistical power is the practical risk of the proposed forward-pass sweep on a single model.
- ATTACK: [gap] It bundles depth allocation and confidence into one joint sweep with no lever to decouple them, so even a positive 'fairness shifted' result cannot attribute the harm to the depth lever vs. the confidence/calibration lever. As evidence for a mechanistic claim it is correlational and un-attributable, which is the weakest form of support.
- SUPPORT: [feasibility] Concrete and cheap: pure forward passes, no retraining, single small open instruction-tuned model (Qwen3-4B / Llama-3.1-8B-Instruct), public bias benchmarks (StereoSet, BOLD, PostTrainingBiasBench). Low compute, 1-2 cycles, fully self-contained.
- SUPPORT: [justification] d3_04 gives a real, non-vacuous phenomenon to measure: uncertainty makes group-asymmetric bias flips 3-11x more likely, so there is observable signal for a confidence-gated (early-exit) policy to redistribute per-group. The audit targets a phenomenon that demonstrably exists.
- SUPPORT: [boundary] d1_03 fixes the interpretation boundary (which model/scale/config actually has exit potential), so a null result is readable as 'this model family has low exit potential' rather than an unexplained artifact — the audit is falsifiable and interpretable.
- SUPPORT: [instrument] d2_01 supplies the exact measurable gate signal (per-group next-token entropy gaps) and p25 guarantees that dropping deep layers is nearly free, so varying exit-depth across a threshold is cheap and the instrument is well-defined.
- REVISED: Revised (id f1): "Rather than audit whether a single shared confidence threshold shifts per-group fairness — which is a strawman because the gate signal (next-token entropy) already differs across groups (d2_01) and aggregate changes cancel (d3_04) — characterize the fairness-amplification of early-exit depth allocation as a design comparison: sweep (a) a single shared calibrated exit threshold vs. (b) a group-conditional calibrated threshold (temperature/Platt, p51/p54) and report the per-group mean-exit-depth vs. per-group error/ECE frontier, classifying per-group depth allocation as fairness-promoting, fairness-neutral, or fairness-penalizing relative to a shared gate. Make the headline output the aggregate-vs-per-group cancellation diagnostic (d3_04's flipped-but-cancelled responses) rather than an aggregate bias delta, so the contribution is framed as 'shared vs. group-conditional gate, and when aggregate metrics hide per-group redistribution' — an actionable calibration choice — not another 'does compression shift bias?' audit (which p38/p50/d3-cluster already cover). Cheap test keeps the single-GPU forward-pass audit but runs both threshold schemas, reporting per-group error/ECE, mean exit-depth, and flip-rate asymmetry under each. Evidence: d2_01 (gate signal differs across groups, so a shared threshold is a strawman), d3_04 (flips cancel in aggregate — motivate a per-group/aggregate diagnostic), d1_01 (calibrated early-exit uncertainty, the actionable group-conditional gate), p51/p54 (temperature and universal calibration machinery for the group-conditional threshold), p25 (depth sweep is nearly free for both schemas), d1_03 (architecture-dependent exit potential fixes how to read a null). ## Debate n1
- ATTACK: GAP attack: n1 is a black-box re-audit with no causal lever and no dropped assumption, so it cannot expose a mechanism. - SUPPORT: d2_01: token-level entropy (the very signal gating CALM/PABEE-style exits) already differs across demographic groups, so the per-token exit decision is a real, measurable carrier of group-conditional computation.

## Debate n2
- ATTACK: [gap] n2 never establishes that 'saturated/collapsed' hidden states are a failure worth fixing. If collapse co-occurs with repetitive/degenerate output rather than with the 'overconfident-but-sustaining' tokens it names, the gate exits at the wrong moment. No evidence in the cluster ties hidden-state saturation to future error or to the 'still-shifting' mode specifically.
- ATTACK: [gap] The failure n2 targets (overconfident-but-still-shifting) is precisely a miscalibration / semantic-uncertainty problem (p52/p53/p56/p57), and a geometry proxy is only indirectly related to it with no demonstrated superiority. There is no shown case where a saturation gate beats a calibrated confidence/entropy gate on accuracy-vs-latency; the premise rests entirely on geometry observations (p69/p70/p64/p71), not on error-prediction evidence, so the criterion's advantage is asserted, not tested.
- ATTACK: [feasibility] The probe is not cheap and not transferable. A cross-layer-similarity and especially a linear-separability readout (p64, d1_04) requires training a per-model, per-task probe on cached or live hidden states — extra training data and compute that eats the exact latency an early-exit is supposed to save, and it must be re-fit whenever the model or task changes.
- ATTACK: [feasibility] d1_03 warns modern LLMs rarely exit early and hidden states may not visibly collapse on real decoding tasks; if saturation rarely triggers, the accuracy-vs-compute frontier collapses to the full forward pass and the gate adds complexity with no latency win. The cheap test on GLUE/SQuAD with PABEE/DeeBERT is a small encoder proxy that says little about decoder LLM token-level generation.
- ATTACK: [feasibility] The saturation boundary is task/dataset/scale dependent, so a single trigger threshold will not transfer, making the method fragile to the very per-instance complexity that other candidates use p11/p25 to embrace.
- ATTACK: [gap] n2 decouples compute from calibrated confidence but provides no measure of when stopping is 'right' for a still-shifting token. Overconfidence that is still shifting is only a problem if it actually costs accuracy or latency; if the overconfident-with-changing-token case is rare or already handled by entropy, the whole motivation collapses and the contribution reduces to 'a probe that occasionally fires.'
