# DSH 0.2.0-rc.1 compatibility verification

Target release: [dsh-v0.2.0-rc.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.1).

## Changes

- Installed global `@deepseek-ai/dsh@0.2.0-rc.1`; CLI version confirmed using an isolated `DSH_HOME`.
- Core and Web DSH peer dependencies are pinned to `0.2.0-rc.1`; Cordis is `~4.0.4`. Updated the core lockfile and added a Web lockfile.
- Replaced the unavailable `dsh-workflow-worker-thread` preset entry with the shipped `dsh-workflow-ptc`. The standard host supplies its `ptcRuntime` dependency.
- Updated the installer to declare `@deepseek-ai/dsh-agent-preset` in the selected profile, with `config.id: auto-research` and `config.plugins`. The new host no longer discovers the old `.agent-presets` installation directory.
- Preserved YAML `!!js` platform conditions as tagged nodes without executing expressions during installation.
- Reinstalls preserve an existing owned preset declaration and its user customizations verbatim; regression coverage checks config/order/tag retention, idempotence, malformed YAML and ownership collisions.

## Test limitations and environment

The initial core full-suite invocation completed with 729 tests: 688 passed and
41 failed (about 9m52s). The corrected failure grouping is paper-pipeline (6),
research-continuation-recovery (5), brainstorm-loop (2), evidence-driven-loop
(12), leakage-loop (1), minimal-loop (14), and direction-memory (1). This
reconciles the count as 34 home-path failures (research-continuation-recovery 5,
brainstorm-loop 2, evidence-driven-loop 12, leakage-loop 1, minimal-loop 14),
6 paper-pipeline cache/compiler environment failures, and 1 direction-memory
failure that has not been reproduced. The 34 home-path failures attempted to
write the default last-run pointer under `os.homedir()/.dsh`; the sandbox
blocked writes to the real Windows profile. No original child stderr was
retained for the direction-memory independent-process upsert failure, whose
test suppresses child stderr, so its exact cause remains unknown.

All 14 minimal-loop tests and all 11 direction-memory tests passed in later
focused runs with an isolated profile. A later full single-process harness run
with both `USERPROFILE` and `DSH_HOME` pointed to a fresh workspace-local
directory completed with 731 tests: 725 passed and 6 paper-pipeline tests
failed. The full run reproduced neither the last-run pointer `EPERM` nor the
direction-memory child failure. The two-test increase from the initial run
reflects later installer-preservation regression coverage. Full output:
`.runs/diagnose-full-tests.log`; focused diagnosis: `.runs/diagnosis-environment.md`.

Follow-up checks with `USERPROFILE` redirected to a temporary workspace folder
passed: `request-accounting.test.ts` 2/2, `service-budget-pause.test.ts` 1/1,
the evidence-driven independent-replication test 1/1, the scientific-assessment
paper handoff test 1/1, and `existing-project-research-e2e.test.ts` 4/4. Before
the test-home adaptation, setting `DSH_HOME` alone did not redirect Node's
`os.homedir()`; targeted runs therefore set `USERPROFILE`. The runner now
creates a disposable `DSH_HOME` before importing tests, and last-run path
resolution uses DSH's home-path helper. This lets the final core-suite rerun
keep the real `USERPROFILE` while using a repository-local Tectonic cache.

An old-dependency rerun of the legacy-artifact evidence-driven test could not
start: the preserved 0.1.5 dependency tree lacks `graphology-utils/is-graph`,
which is required during import. The final full run against rc.1 passed, but a
test-by-test comparison against that preserved dependency tree remains
unavailable.

The existing uncommitted changes to research records and tools were preserved.
Old local dependency trees were retained under `.runs/dsh-upgrade-backup/`.
Initial npm downloads encountered connection resets; subsequent cache-assisted
installs completed. The download retries do not change the pinned target version.

## Test-home and compiler environment correction (2026-10-01)

Core last-run state now resolves its home at call time through DSH's
`resolveDshHome()` helper, with precedence `profileDir` argument, `DSH_HOME`,
then the default `~/.dsh`. The helper is a direct core dependency pinned at
`0.2.0-rc.1`; core and Web lockfiles were synchronized. The test runner creates
one temporary `DSH_HOME` before importing test modules and removes it with both
the `node:test` after hook and an exit fallback. A focused session test run
passed 7/7, and the core build passed after this change.

Review found that the Web lockfile needed to reflect the matching home-path
dependency snapshot; this was corrected before the final core run. A direct
Tectonic check also confirmed that setting `TECTONIC_CACHE_DIR` alone to the
repository-local cache produces a PDF, without changing `USERPROFILE`.
